# ADR-0003: マルチフォーマット画像抽出戦略の策定

## ステータス
Accepted

## コンテキスト (Context)
Gemini-CLI 等のマルチモーダル LLM を活用する際、ドキュメント内のテキスト情報だけでなく、図解、システム構成図、フローチャート、数式などの視覚的情報を直接 AI に読み取らせるニーズが発生した。
従来の Markdown 形式へのテキスト抽出のみでは、これらの視覚的コンテキストが欠落し、AI の理解精度が低下する課題があった。

## 決定事項 (Decision)
PDF, PowerPoint, Excel の主要な Office ドキュメントに対し、以下の指針に基づいて画像抽出機能を実装する。

1. **AIフレンドリーな単一ステップ設計 (Handle-based Single-step Interface)**
   - AI エージェントの操作ターン数とコンテキスト消費を最小化するため、変換プロセスを隠蔽し、一回のツール実行で最終的な画像ファイルのパスを返却する設計とする。
   - 変換過程で生成される中間ファイル（例: Excel から PDF への変換など）は、ツール内部で自動的にクリーンアップする。

2. **フォーマット別の最適な抽出手法の採用**
   - **PDF**: 外部ソフトウェア（Poppler等）への依存を排除し、爆速かつ高品質なレンダリングを実現するため `PyMuPDF` (fitz) を採用する。
   - **PowerPoint**: フォントやレイアウトの完全な再現性を確保するため、Windows 環境での `pywin32` (COM) 操作によるスライドエクスポートを採用する。
   - **Excel**: クリップボード競合のリスク（ユーザー操作との干渉）を避け、安定したサーバー動作を実現するため、一度 PDF にエクスポートしてから画像化するハイブリッド方式を採用する。

3. **「Fit-to-Page」ハックによる図解の再現度向上**
   - Excel の画像化において、巨大な図が改ページで分断されるのを防ぐため、PDF 出力直前に `PageSetup` を動的に操作し、横幅を強制的に 1 ページに収める（Fit-to-Page Wide=1）ハックを標準適用する。

4. **内部ロジックの再利用 (Internal DRY, External Specialty)**
   - 実装コードレベルでは、Excel の画像化処理の中で PDF 画像化ロジックを直接呼び出すなど、重複を避ける。
   - 一方で、MCP ツール（インターフェース）としては各ドキュメント専用のツールとして独立させ、AI が「何に対して何をするか」を直感的に判断できるようにする。

## 影響 (Consequences)

### メリット
- AI が複雑な図解やフローチャートを直接視認し、高い精度で要件定義や設計の理解が可能になる。
- ユーザー（AI）側の実装が簡素化され、一時ファイルの消し忘れによるリソース圧迫を防止できる。
- クリップボードを使用しない PDF 経由の Excel 変換により、サーバー環境での並列実行安定性が向上する。

### デメリット / 制約
- PowerPoint および Excel の画像化は Windows 環境かつ Microsoft Office のインストールが必須となる。
- `PyMuPDF` の導入により、ライセンス面（AGPL）での配慮が必要になる可能性がある。
