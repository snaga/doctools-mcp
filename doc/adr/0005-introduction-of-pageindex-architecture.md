# ADR-0005: PageIndex アーキテクチャの導入 (Reasoning-based RAG)

## ステータス
Accepted

## コンテキスト
大規模なドキュメント（数百ページ超の PDF やパワポ資料）を AI エージェントが扱う際、従来のベクトル検索（Semantic Search）では「全体像の把握」や「論理構造に基づいた正確な引用」が困難であるという課題があった。また、ドキュメント全文をコンテキストに読み込むことは、トークンコストの増大と推論精度の低下（Lost in the middle）を招く。

## 決定事項
ベクトル検索に頼らない、LLM の推論能力を活用した階層型インデックス「PageIndex」を採用する。

1.  **階層構造の定義**: ドキュメントを章・節・項（またはスライド、シート）単位でツリー構造化し、各ノードにキーワード密度の高いサマリーを付与する。
2.  **段階的探索（Step-by-step Exploration）**: AI エージェントがインデックスのルートから開始し、必要に応じて下位ノードを段階的に取得（`pageindex_get_tree`）して探索範囲を絞り込むフローを標準とする。
3.  **ピンポイント抽出（Targeted Retrieval）**: 探索の結果特定された最小単位（リーフノード）のみをフルテキストとして抽出（`pageindex_get_node_content`）し、回答生成の根拠とする。
4.  **分散管理**: インデックスファイル（`.pageindex.json`）は対象ドキュメントと同じディレクトリに配置し、ドキュメントと地図を 1 対 1 で管理する。

## 影響・結果

### メリット
- **圧倒的なトークン節約**: 全文を読み込む場合に比べ、探索と抽出のセットで 90% 以上のトークン消費削減が可能。
- **高い信頼性**: AI がドキュメントの「目次」を理解して探索するため、ベクトル検索の「雰囲気検索」による見逃しや誤情報を大幅に低減できる。
- **スケーラビリティ**: 数千ページ規模のドキュメント群に対しても、深層ツリー構造によって効率的に対応できる。

### デメリット / 注意点
- **探索回数の増加**: 正解に辿り着くまでに複数回の MCP ツール呼び出し（思考ステップ）が発生するため、単純な検索に比べるとターン数が増加する。
- **構築コスト**: インデックス構築時に LLM による要約生成（`pageindex_ctl build`）が必要となる。
