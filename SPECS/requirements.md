# 概要
Gemini-CLI 等の AI エージェントが、PDF, PowerPoint, Excel, CSV, HTML などのローカルドキュメントを自由に閲覧・検索・加工できるようにするための MCP (Model Context Protocol) サーバーを提供する。

## 前提条件
- Python ランタイム環境が利用可能であること。
- 検索インデックスを利用する場合、`.env` ファイル等で保存先パスが設定可能であること。

## 制約条件
- `fastmcp` ライブラリを使用すること。
- ドキュメントからのテキスト抽出（Markdown等）の結果が大きくなる可能性があるツールは、内容を直接返さず、ファイルに書き出した上でそのパスを返却すること（ハンドルベース・アーキテクチャ）。

## 要件

### 要件カテゴリ: PDF操作 (PDF)

- 要件 PDF-01: PDFページ切り出し
   - ユーザーストーリー
      - 私はGemini-CLIのユーザーとして、PDFの特定ページを切り出したい。なぜなら生成AIに読ませるための必要最小限のデータを持つPDFファイルを作成するためだ。
   - 受け入れ基準
      - 有効な入力ファイルと抽出範囲（開始・終了ページ）が指定されたとき、システムは、指定された範囲のページのみを含む PDF ファイルを生成しなければならない。
      - PDF の生成に成功したとき、システムは、出力ファイルの絶対パスを含む成功応答を返さなければならない。

- 要件 PDF-02: PDFテキスト抽出 (Markdown)
   - ユーザーストーリー
      - 私はGemini-CLIのユーザーとして、PDFのスライド内容をMarkdownファイルとして保存したい。なぜならAIによる要約やコンテンツの再利用を効率化しつつ、コンテキストの消費を抑えるためだ。
   - 受け入れ基準
      - 有効な PDF ファイルが入力されたとき、システムは、指定された範囲のテキストを抽出し、Markdown フォーマットのファイルとして保存しなければならない。
      - Markdown ファイルの保存に成功したとき、システムは、生成されたファイルの絶対パスを返さなければならない。
      - 出力ファイルパスが指定されていないとき、システムは、入力ファイルと同一のディレクトリに `.md` 拡張子のファイル名で保存しなければならない。

- 要件 PDF-03: PDFページ数カウント
   - ユーザーストーリー
      - 私はGemini-CLIのユーザーとして、PDFの総ページ数を確認したい。なぜなら操作対象のページ範囲を適切に判断するためだ。
   - 受け入れ基準
      - 有効な PDF ファイルが入力されたとき、システムは、そのファイルの総ページ数を解析しなければならない。
      - ページの解析が完了したとき、システムは、総ページ数を含む成功応答を返さなければならない。

- 要件 PDF-04: PDF ページ画像化 (PNG/JPG)
   - ユーザーストーリー
      - 私はGemini-CLIのユーザーとして、PDFの特定のページを画像（PNG等）として保存したい。なぜなら、ページ内の図、表、数式などの視覚的情報をAIに直接見せて理解させるためだ。
   - 受け入れ基準
      - 有効な PDF ファイルと対象のページ番号（単一またはリスト）が指定されたとき、システムは、指定された各ページを画像ファイルとして保存しなければならない。
      - ページ画像化要求があったとき、システムは、解像度（DPI）の指定を受け入れなければならない。
      - 画像の生成に成功したとき、システムは、生成されたすべての画像ファイルの絶対パスを含む成功応答を返さなければならない。

   - ユーザーストーリー

   - 受け入れ基準

- 要件 PPTX-04: PowerPoint スライド画像化 (PNG/JPG)
   - ユーザーストーリー
      - 私はGemini-CLIのユーザーとして、PowerPointの特定のスライドを画像（PNG等）として保存したい。なぜなら、スライド内の構成図やグラフなどの視覚的情報をAI（Gemini等）に直接見せて理解させるためだ。
   - 受け入れ基準
      - 有効な PPTX ファイルと対象のスライド番号（単一またはリスト）が指定されたとき、システムは、指定された各スライドを画像ファイルとして保存しなければならない。
      - スライド画像化要求があったとき、システムは、解像度（幅・高さ）の指定を受け入れなければならない（指定がない場合は 1280x720 をデフォルトとする）。
      - 画像の生成に成功したとき、システムは、生成されたすべての画像ファイルの絶対パスを含む成功応答を返さなければならない。
      - 実行環境が Windows かつ PowerPoint がインストールされているとき、システムは、`pywin32` を使用して高精度な変換を行わなければならない。

- 要件 PPTX-05: PowerPoint 結合 (Merge)
   - ユーザーストーリー
      - 私は Gemini-CLI のユーザーとして、複数の PowerPoint ファイルを1つにまとめたい。なぜなら、別々の資料を1つのプレゼンとして統合して効率的に扱いたいからだ。
   - 受け入れ基準
      - 複数の有効な PPTX ファイルのパスリストと出力パスが指定されたとき、システムはそれらを指定された順番で結合した新しいファイルを生成しなければならない。
      - 実行環境が Windows かつ PowerPoint がインストールされているとき、システムは `pywin32` を使用して、元のレイアウトやマスターを維持したまま結合を行わなければならない。
      - 結合に成功したとき、システムは出力ファイルの絶対パスを含む成功応答を返さなければならない。

      - Markdown ファイルの保存に成功したとき、システムは、生成されたファイルの絶対パスを返さなければならない。

- 要件 XLSX-04: Excel シート名一覧取得

      - シート名の解析が完了したとき、システムは、シート名のリストを含む成功応答を返さなければならない。

- 要件 XLSX-05: Excel シート画像化 (PNG/JPG)
   - ユーザーストーリー

   - 受け入れ基準
      - 有効な Excel ファイルと対象のシート名（単一またはリスト）が指定されたとき、システムは、指定された各シートを画像ファイルとして保存しなければならない。
      - シート画像化要求があったとき、システムは、横幅を 1 ページに収める最適化（Fit-to-Page）を適用した上で、PDF を経由して画像化しなければならない。
      - 画像の生成に成功したとき、システムは、生成されたすべての画像ファイルの絶対パスを含む成功応答を返さなければならない。

### 要件カテゴリ: 検索・インデックス (SEARCH)

- 要件 SEARCH-01: Office 文書のインデックス作成
   - ユーザーストーリー
      - 私はシステム管理者として、Office 文書の検索用インデックスを作成したい。なぜなら AI が大量の文書から情報を効率的に検索できるようにするためだ。
   - 受け入れ基準
      - インデックス対象のディレクトリが指定されたとき、システムは、その配下の Office 文書（PDF, PPTX, XLSX, DOCX）およびテキスト文書（TXT, MD）を再帰的にスキャンしなければならない。
      - スキャンした文書の解析が完了したとき、システムは、指定された保存先に全文検索用インデックスを構築しなければならない。

- 要件 SEARCH-02: 全文検索機能
   - ユーザーストーリー
      - 私は Gemini-CLI のユーザーとして、ドキュメントを全文検索したい。なぜならキーワードに関連するファイルを即座に見つけ出すためだ。
   - 受け入れ基準
      - 有効なインデックスが存在し、かつ検索キーワードが入力されたとき、システムは、インデックス内のドキュメントを検索しなければならない。
      - キーワードに合致するドキュメントが見つかったとき、システムは、該当するドキュメントの絶対パスの一覧を返さなければならない。

- 要件 SEARCH-03: インデックス保守機能
   - ユーザーストーリー
      - 私はシステム管理者として、検索インデックスの内容を確認したい。なぜなら、どのようなインデックスが利用可能か、また特定のインデックスにどのファイルが含まれているかを把握するためだ。
   - 受け入れ基準
      - インデックス名が指定されずに list コマンドが実行されたとき、システムは、利用可能なすべてのインデックス名とその概要を表示しなければならない。
      - 有効なインデックス名が指定されて list コマンドが実行されたとき、システムは、そのインデックスに登録されているすべてのファイルのパスを表示しなければならない。
      - インデックス構築・更新コマンド（build）と対象パスが指定されたとき、システムは、指定されたパス配下の文書を再スキャンし、インデックス情報を更新しなければならない。
      - 削除コマンドと対象パスが指定されたとき、システムは、指定されたパスに一致する文書情報をインデックスから削除しなければならない。

- 要件 SEARCH-04: ディレクトリによる検索絞り込み (Faceting)
   - ユーザーストーリー
      - 私は Gemini-CLI のユーザーとして、ドキュメント検索の範囲を特定のディレクトリ配下に限定したい。なぜなら、関係のないファイルを除外して、目的の情報を効率的に見つけたいからだ。
   - 受け入れ基準
      - 対象ディレクトリが指定されたとき、システムは、指定されたディレクトリとそのサブディレクトリに含まれるドキュメントのみを検索対象としなければならない。
      - 対象ディレクトリが指定されたとき、システムは、絶対パスまたは相対パスのいずれの形式も受け入れなければならない。

- 要件 SEARCH-05: インデックス切り替え検索
   - ユーザーストーリー
      - 私は Gemini-CLI のユーザーとして、検索対象のインデックスを指定して文書を検索したい。なぜなら、複数のプロジェクトやドキュメントセットを使い分け、関係のない情報を除外して精度を上げたいからだ。
   - 受け入れ基準
      - 検索ツール呼び出し時にインデックス名が指定されたとき、システムは指定されたインデックスを使用して検索を行わなければならない。
      - インデックス名が指定されなかったとき、システムはベースディレクトリ直下の `default` インデックスディレクトリを使用して検索を行わなければならない。
      - 指定されたインデックス名に不正な文字（パス区切り文字や相対パス記述など）が含まれていた場合、システムはエラーを返し、不正なパスへのアクセスを防がなければならない。

- 要件 SEARCH-06: インデックス一覧取得 (概要付き)
   - ユーザーストーリー
      - 私は Gemini-CLI のユーザーとして、利用可能なインデックスの名前とその概要（説明）の一覧を知りたい。なぜなら、自分の目的に合ったインデックスがどれかを AI に正しく判断させたいからだ。
   - 受け入れ基準
      - 一覧取得要求があったとき、システムは利用可能なすべてのインデックス名と、それぞれの説明文（Description）のリストを返さなければならない。

- 要件 SEARCH-07: インデックス作成時の説明登録
   - ユーザーストーリー
      - 私はシステム管理者として、インデックスを作成・更新する際にその内容の説明を登録したい。なぜなら、後で AI や利用者がそのインデックスの用途を理解できるようにするためだ。
   - 受け入れ基準
      - インデックス作成・更新コマンド実行時、オプションで説明文を指定できた場合、システムはその説明文をインデックスに関連付けて保存しなければならない。

- 要件 SEARCH-08: マルチインデックス環境対応
   - ユーザーストーリー
      - 私はシステム管理者として、複数のインデックスを一箇所で管理したい。なぜなら、プロジェクトごとに異なるインデックスフォルダを散乱させず、統一的なベースディレクトリ配下で管理したいからだ。
   - 受け入れ基準
      - システムは、環境変数 `WHOOSH_INDEX_BASE_DIR` で指定されたベースディレクトリ配下のサブディレクトリのみを、インデックスの格納場所として認識しなければならない。
      - レガシーな環境変数 `WHOOSH_INDEX_DIR` は廃止し、すべてのインデックス管理をベースディレクトリに一本化しなければならない。

- 要件 SEARCH-09: CLIでの対象インデックス指定
   - ユーザーストーリー
      - 私はシステム管理者として、特定のインデックスを指定して保守作業（作成・更新・削除）を行いたい。なぜなら、特定のプロジェクトのドキュメントだけを更新したり、不要になったインデックスだけを削除したいからだ。
   - 受け入れ基準
      - CLIツール (`index_ctl`) の `build`, `update`, `delete` コマンドは、操作対象のインデックス名を引数として受け入れなければならない。
      - CLIツール (`index_ctl`) の `list` コマンドは、操作対象のインデックス名を任意引数として受け入れなければならない。

- 要件 SEARCH-10: インデックス対象拡張子の任意指定
   - ユーザーストーリー
      - 私はシステム管理者として、インデックス作成時にスキャン対象とするファイルの拡張子を自由に指定したい。なぜなら、プロジェクトに合わせて設計書（Office文書）だけでなく、ソースコード（.py, .sql等）も検索対象に含めたいからだ。
   - 受け入れ基準
      - インデックス構築・更新コマンド（build）実行時、オプションで対象拡張子のリストが指定されたとき、システムは指定された拡張子を持つファイルのみをスキャンし、その設定をインデックスのメタデータとして保存しなければならない。
      - 設定された拡張子の情報は、次回のインデックス更新時（build）にオプション指定がなかった場合でも引き継がれなければならない。
      - オプションおよびメタデータに拡張子の指定がなかったとき、システムはデフォルトの拡張子セット（.pdf, .pptx, .xlsx, .docx, .txt, .md）を使用してスキャンしなければならない。
      - 拡張子の指定は、カンマ区切り、またはスペース区切りなど、複数の拡張子を一度に指定できる形式でなければならない。
      - インデックス一覧表示時、それぞれのインデックスが対象としている拡張子のリストを確認できなければならない。

- 要件 SEARCH-14: インデックスの一括メンテナンス (統合ビルド)
   - ユーザーストーリー
